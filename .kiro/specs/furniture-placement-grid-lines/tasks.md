# Implementation Plan

## Branches

**Base**: `feature/furniture-placement-grid-lines`

All tasks are implemented in the base branch.

## Tasks

### Branch: `feature/furniture-placement-grid-lines`

- [x] 1. (P) フットプリントの可否・可視セル判定を純粋ロジックとして実装する
  - [x] 1.1 (P) UnityEngine 非依存のロジックアセンブリを用意し、セル列挙と評価を実装する
    - フットプリントの開始位置とサイズから全セルを列挙する (x 外側・y 内側の順)
    - 範囲内判定と占有 id 取得は呼び出し側から関数で受け取り、面の種別を知らない構造にする
    - 全セルが範囲内かつ未占有 (または自分の id) のときだけ配置可とし、範囲内セルのみを可視セルとして返す
    - 全セルが範囲外なら可視セルを空にし配置不可とする
  - [x] 1.2 (P) EditMode テストで境界値を固定する
    - 全セル可 / 他家具が占有 / 一部が範囲外 / 全域が範囲外 / 自分の id は占有扱いしない の 5 ケース
    - 各テストに日本語の Description を付ける
  - _Requirements: 6.3, 6.4, 6.5, 6.6, 6.10_

- [x] 2. ドラッグ中の落下先解決を一本化する
  - [x] 2.1 落下先を表す不変の値型を導入し、ドラッグサービスに解決メソッドを追加する
    - 面の種別 (床 / 壁 / 家具上)、壁の側、家具上グリッド参照、フットプリント開始位置、配置可否を 1 つの値で持つ
    - 解決順序は既存どおり「家具上 (Raycast ヒットかつ配置可) → 床」、壁家具は壁のみ。壁の左右反転処理より後に解決する
    - 解決メソッドは State を変更しない
  - [x] 2.2 ドラッグ中と離した時の既存判定を解決メソッドに置き換える
    - ドラッグ中の再親子付けと SortingOrder 更新は落下先を入力にして既存の位置に残す
    - 離した時は落下先で配置し、配置不可なら元位置へ戻す既存挙動を維持する
    - 床 / 壁 / 家具上 / 範囲外 / 占有済み / しまう の 6 経路を Editor で手動確認し、従来と同じ挙動であることを確かめる
  - _Requirements: 3.3, 6.10_

- [x] 3. 予告サービスを追加し、ドラッグのライフサイクルに接続する
  - [x] 3.1 落下先から描画命令を組み立てる予告サービスを実装する
    - ドラッグ開始で対象面 (壁家具なら両壁、それ以外は床) の線表示を指示する
    - ドラッグ移動で落下先の面に応じた範囲判定・占有取得をロジック層に渡し、可視セルの四角形 (ワールド座標 4 頂点) と可否色を View に渡す。可視セルが無ければ予告を消す
    - 家具上の落下先ではその家具のグリッド座標系で頂点を求め、親 Transform を View に渡す
    - ドラッグ終了で線と予告を非表示にする
    - View 未登録なら何もせず、警告ログを一度だけ出す。State は読み取りのみ
  - [x] 3.2 グリッド線の頂点列を面ごとに一度だけ生成する
    - 床 / 左壁 / 右壁それぞれの縦横線を、既存の座標変換 (原点・セルサイズ・角度・幅・高さ・壁高さ) から線分列として生成し View に渡す
    - Editor 用 Gizmo と同じ格子になることを重ねて確認する
  - [x] 3.3 DI 登録とドラッグサービスからの呼び出しを配線する
    - シーンスコープに予告サービスを Scoped 登録し、ドラッグサービスのコンストラクタに追加する
    - ドラッグ開始 / 移動 / 終了の 3 か所から呼ぶ。終了はドラッグ対象の null 早期 return より前 (しまう経路でも呼ばれる位置) に置く
  - _Requirements: 1.1, 1.2, 1.4, 2.1, 2.2, 2.3, 4.3, 5.1, 5.2, 6.1, 6.2, 6.7, 6.8, 6.9_

- [x] 4. グリッド線と予告面を手続きメッシュで描画する View を実装する
  - [x] 4.1 線用と予告用の 2 つの描画オブジェクトを持つ View を実装する
    - 線: 面ごとに線分列を細長い四角形へ展開したメッシュをキャッシュし、表示面を切り替える。SortingOrder は -10 を既定とする
    - 予告: 受け取った四角形列を毎フレーム再構築する。頂点・色・インデックスのバッファを再利用し、MarkDynamic と RecalculateBounds を行う。SortingOrder は床・壁で -9 を既定とする
    - Collider を持たず、マテリアルはインスタンス化しない。初期状態は非表示
    - 線色 (透明度含む)、線幅、通常色、不可色、各 SortingOrder、マテリアルを Inspector で設定可能にする
    - マテリアル未設定なら起動時にエラーログを出して描画を無効化し、ドラッグは継続させる
  - [x] 4.2 View を予告サービスに自己登録し、シーンに配置する
    - View の Inject メソッドで予告サービスに自分を登録する
    - Home シーンに GridPreview オブジェクトと子 2 つを置き、URP 2D の Sprite-Unlit-Default マテリアルを割り当て、シーンスコープの autoInjectGameObjects に追加する
    - 床家具をドラッグして床線と予告が出て、離すと消えることを Editor で確認する。GridPreview を無効化してもドラッグが従来どおり動くことを確認する
  - _Requirements: 1.1, 1.2, 1.3, 1.5, 2.1, 2.2, 3.1, 3.2, 4.1, 4.2, 4.3, 6.1, 6.3, 6.4, 6.11, 6.12_

- [x] 5. 家具上グリッドの予告を親家具の手前・子家具の奥に描く
  - [x] 5.1 家具上グリッドに面 SortingGroup を挿入する
    - 家具上グリッドの起動時に SortingGroup が無ければ追加し、order 1、sortAtRoot 無効にする。プレハブは編集しない
    - 家具上グリッドを持つ全 7 プレハブ (Bed / LargeBox / MicrowaveOven / Refrigerator / SideTable / Table) に家具を載せ、既存の見え方が崩れないことを Editor で確認する。この変更は単独コミットにする
  - [x] 5.2 予告面を家具上グリッドの子として描画する
    - 落下先が家具上のとき予告オブジェクトをそのグリッドの子に付け替え、SortingOrder を面グループ内の -1 (Inspector 設定) にし、頂点をローカル座標へ変換する
    - 落下先が床・壁に戻ったとき、およびドラッグ終了時に View 自身の子へ戻す
    - Bed 上でドラッグして予告が Bed のスプライトの手前・ドラッグ中家具の奥に出ること、占有セルでは床側の予告が赤になることを確認する
  - _Requirements: 6.7, 6.12_

- [ ] 6. 全経路の統合確認と実機検証を行う
  - [ ] 6.1 Editor で受入経路を一通り確認する
    - 壁家具: 左右の壁線が出て床線が出ない。左右の壁をまたいでも予告が追従する
    - 範囲外: はみ出したセルは描かれず、範囲内のセルが赤になる。全域が範囲外なら予告が出ない
    - 占有済み: 予告が赤になり、離すと元位置に戻る
    - しまう経路とドラッグ中の Redecorate 離脱で線と予告が残らない
    - セーブデータと IsoGridState が変化していない
  - [ ] 6.2 実機で描画とフレームレートを確認する
    - Android または iOS で線と予告が透過描画されることを確認する
    - ドラッグ中のフレームレートが従来と体感差ないことを確認する
  - _Requirements: 1.5, 2.2, 3.3, 5.1, 5.2, 6.5, 6.6, 6.8, 6.9_
